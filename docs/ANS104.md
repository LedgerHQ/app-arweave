# Experimental ANS-104 Data Item signing

This branch adds bounded parsing and RSA-4096 signing for canonical ANS-104
Data Items. It is development software and is not approved for production use.

## Safety boundary

- Use only a dedicated development Ledger initialized with a test seed.
- Never load this build on a device that protects funded accounts.
- Only Arweave signature type `1` is accepted.
- The 512-byte owner must equal the public key derived by the device.
- At most 16 tags and one buffered Data Item are accepted.
- Duplicate tags and non-printable tag names or values are rejected.
- The device parses the ANS-104 binary and Avro tag block itself. It never
  signs a digest supplied by the host.
- Target, anchor, every tag, data length, and a SHA-384 data hash are shown
  before approval.
- This implementation has not completed Ledger validation or an independent
  security audit.

## APDU

`SIGN_DATA_ITEM` uses `CLA=0x44`, `INS=0x03`, `P2=0`, and the existing chunk
protocol:

| P1 | Meaning |
| --- | --- |
| `0x00` | Initialize an empty buffer |
| `0x01` | Append a chunk |
| `0x02` | Append the final chunk, parse, and open review |

The bytes after reassembly are one canonical ANS-104 Data Item:

| Field | Encoding |
| --- | --- |
| Signature type | 2-byte little-endian integer; must be `1` |
| Signature | 512 bytes; ignored while computing signature data |
| Owner | 512 bytes; must match the device key |
| Target present | one byte, `0` or `1` |
| Target | 32 bytes when present |
| Anchor present | one byte, `0` or `1` |
| Anchor | 32 bytes when present |
| Tag count | 8-byte little-endian integer |
| Tag byte length | 8-byte little-endian integer |
| Tags | canonical Avro-encoded ANS-104 tags |
| Data | all remaining bytes |

After approval, the response contains the 48-byte deep hash followed by
`0x9000`. The 512-byte RSA-PSS signature is retrieved through the existing two
`GET_SIG` calls.

## Signature data

The device computes the ANS-104 deep hash over this eight-element list:

1. `dataitem`
2. `1`
3. `1` (Arweave signature type)
4. raw owner
5. raw target or an empty blob
6. raw anchor or an empty blob
7. raw Avro tag bytes
8. raw data

The resulting 48-byte SHA-384 deep hash is hashed with SHA-256 and signed using
RSA-PSS, matching the existing Arweave key and signature scheme.

## Validation stages

1. Native parser vectors and malformed-input tests.
2. AddressSanitizer, UndefinedBehaviorSanitizer, and libFuzzer runs.
3. Speculos/Ragger review, rejection, and signing checks on every supported model.
4. Sideload to a dedicated development Ledger with a test seed and compare the
   returned signature with `arbundles` verification.
5. Open a draft update PR for Ledger review.
6. Complete Ledger functional validation and address review findings.
7. Commission the required independent security audit before production.

The current Ledger builder produces SDK API-level-26 Nano S Plus and Nano X
binaries. `make current_ragger` builds a test-only firmware containing a public,
disposable RSA key fixture, runs the review flow in Speculos, retrieves the
signature, and verifies it independently. Production builds never include that
fixture and continue deriving their keys from the device seed.
